# 环境准备与实验复现

当前仓库提供路线和记录框架，尚无经过本仓库验证的板端运行入口。以下步骤用于首次复现；具体板卡操作、供电、启动方式和射频限制以对应厂家指南为准。

## 环境清单

开始实验前复制 [实验模板](experiment-template.md)，记录：

- 板卡型号与硬件版本、使用者及实验时间。
- PYNQ 镜像文件名、版本、来源与 SHA-256。
- Python、NumPy、PYNQ 和 OFDM 包版本。
- bit/hwh 文件名、SHA-256、包来源及匹配关系。
- 若重建工程，记录 Vivado、IP、约束与所需其他工具版本。
- 仓库提交号（`git rev-parse HEAD`）、工作区是否有未提交修改（`git status --short`）。

本地可用 PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath '实际文件路径'` 计算文件校验值。路径只是本地索引；同时记录可供协作者取得同一文件的方式。

## 外部资料

已有学习路线提及厂家 `5_PYNQ` 资料、`PZ-P047PRO.img`、`rfsoc_ofdm` 包及本板的 `.bit/.hwh`。这些文件未随当前仓库发布；先核对本地是否实际具备，再记录版本。原路线中的厂家 PDF 相对链接不会在 GitHub 上打开。

从厂家适配包优先寻找：

- `rfsoc_ofdm/boards/rfsoc47dr/rfsoc_ofdm/bitstream/`。
- `02_rfsoc_ofdm_demonstrator.ipynb`。
- 配套安装说明、时钟/RFDC 驱动与运行依赖。

归档内目录和来源说明参见 [学习路线第 3 节](../P047Pro_OFDM到AFDM学习开发路线.md)。找不到对应文件时记录缺口，不能用其他板型文件直接视为等价替代。

## 首次 OFDM 回环

1. 核对板卡供电、散热与启动配置，保留原 SD 卡资料后再安排镜像写入。
2. 启动厂家 PYNQ，确认串口日志、网络与 Jupyter 可访问。私人地址和登录信息留在本地。
3. 核对厂家 OFDM 包、板型选择与 bit/hwh 配套关系，保存安装及导入结果。
4. 按对应厂家指南核对 TX4 → RX2 接线、适用的射频衰减和幅度设置，再执行加载与收发。
5. 先观察 BPSK/QPSK，触发新采集，记录调制变化和接收结果是否一致。
6. 若接口可用，保存 I/Q 与采样率、采集点、数据类型、长度和缩放信息。
7. 完成三次独立启动或重新初始化，记录每次成功与失败条件。

## 判定与归档

能显示星座不等于已经验证自定义消息、BER 或 AFDM。分别标注“启动通过”“OFDM 观察通过”“数据校验通过”等实际达到的结论。

原始采样可保存在本地 `captures/`，生成产物可放在 `artifacts/`；两者默认忽略。在 Git 中提交参数、脱敏日志摘要、可公开的小图表和样本的校验值/存储说明。未经公开许可的厂家材料和研究资料留在本地。

遇到问题时，记录执行入口、完整错误的脱敏版本、预期与实际结果、最近改动，以及可重复执行的步骤。硬件验证尚未执行时，不填写“通过”。
